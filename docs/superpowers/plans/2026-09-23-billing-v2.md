# Billing v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended when delegation works) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace collections with the agreed billing calendar at `/billing`, preserve legacy code/data, and reuse domain-neutral presentation across features.

**Architecture:** Separate the `cobranzas` permission value from its public `/billing` route. Billing v1 remains isolated; billing v2 owns its domain/adapters and uses a shared data repository. Calendar, Table and Kanban are shared presentation concepts; feature adapters retain permissions, schemas, mutations and business rules.

**Tech Stack:** Existing Next.js 14 App Router, React 18, TypeScript, Supabase/Postgres/RLS, Zod, date-fns/date-fns-tz, Recharts, project CSS/UI/i18n, Vitest and Playwright. No new dependency assumed.

- The internal permission value remains `cobranzas`; preserve existing finance grants.
